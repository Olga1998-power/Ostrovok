# 🎴 Островок.Match — iOS MVP 

**Островок.Match** — это концепт умного мобильного приложения для iOS, который геймифицирует и упрощает процесс планирования путешествий. Проект разработан в рамках трека **«О!дин шаг до идеального отеля»**.

Вместо бесконечного и скучного листания сотен отелей и чтения сотен отзывов, пользователь выбирает путешествие мечты с помощью **Tinder-механики свайпов** и умного **ИИ-Консьержа**.

---

## 🎯 Продуктовая идея & UI/UX

Приложение решает проблему «паралича выбора» у туриста, сокращая метрику **Time-to-Book** в несколько раз. 

### Интерфейс и Фичи:
1. **🎨 Минималистичный UI/UX:** Оформление в фирменных зеленых и белых цветах Островка.
2. **🤖 Умный Онбординг:** На старте ИИ-маскот (персонаж-агент) предлагает экспресс-опрос: выбрать желаемые страны и важные теги (активный отдых, спа, бюджетно). Доступна кнопка **«Пропустить»** для мгновенного перехода к универсальной ленте.
3. **🎴 Главный экран (Свайпы):** Механика Тиндера. Карточка на 70% состоит из фото отеля/тура/перелета. Поверх фото отображается **AI-выжимка отзывов** (`ai_summary`), которая за 1 секунду объясняет главные плюсы и минусы места. 
   * **Свайп вправо** — Лайк (сохранение в отложенное).
   * **Свайп влево** — Дизлайк.
4. **📱 Нижняя панель навигации (Tab Bar):**
   * **Карточки** (Главный экран свайпов).
   * **ИИ-Агент** (Консьерж-чат для бронирования, связи с менеджером и умных подборок).
   * **Матчи** (Список лайкнутых карточек).
   * **Профиль** (Личный кабинет).

---

## ⚙️ Техническая архитектура

Проект построен по принципу полноценного, честного MVP (микросервисы и работа с данными в реальном времени без фейковых заглушек).

* **Frontend:** Мобильное приложение под iOS (Swift / Flutter).
* **Backend:** Высокопроизводительный сервер на **Go** (фреймворк Gin/Fiber).
* **База данных:** **PostgreSQL 15** внутри Docker-контейнера.
* **Интеграция ИИ:** Динамические запросы к API LLM (ChatGPT/YandexGPT) для разбора текстовых запросов пользователя в чате на лету.

---

## 📊 Алгоритм работы рекомендаций и ИИ (Без усложнения архитектуры)

1. **Сбор неявных предпочтений:** Когда пользователь свайпает карточки, мобильное приложение отправляет события на Go-бэк. Данные честно записываются в PostgreSQL в таблицу `user_swipes`.
2. **Умный подбор:** Бэкенд анализирует массив JSONB-тегов (`amenities`) у лайкнутых пользователем карточек и при следующем запросе выдает из БД похожие предложения в приоритетном порядке.
3. **Динамический AI-чат:** При запросе в свободной форме в чате (например, *«хочу в Сочи со спа»*), Go отправляет текст в LLM, получает структурированные фильтры и делает прямой SQL-поиск по базе данных.

---

## 📁 Структура папок аналитики
Все наработки по структуре данных и наполнению базы находятся в папке `/analytics`:
* `init.sql` — схема таблиц PostgreSQL (JSONB, индексы).
* `mock_data.sql` — тестовый датасет из 5 полноценных карточек с реальными изображениями и сгенерированными AI-выжимками отзывов.
