# Островок Intelligence — Telegram Mini App

Рабочий автономный демонстрационный сервис по поиску отелей с объясняемыми рекомендациями, проверяемыми характеристиками, географическим расчётом и кабинетом отельера.

## Запуск за несколько минут

Требуется Python 3.11+.

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8080
```

Windows: `.venv\Scripts\activate` вместо `source ...`.

Открыть `http://127.0.0.1:8080`. Документация API: `http://127.0.0.1:8080/docs`. База SQLite заполняется автоматически при первом запуске из `data/seed.json`. Необходимости в LLM-ключе нет.

Альтернатива: `docker compose up --build`.

## Telegram

1. Создайте бота в @BotFather; получите `TELEGRAM_BOT_TOKEN`.
2. Опубликуйте сервис по HTTPS (например, на VPS за reverse proxy).
3. Настройте Mini App в BotFather, указав HTTPS URL приложения. Откройте Mini App из Telegram.
4. Для серверных вызовов авторизации используйте `GET /v1/auth/telegram` с заголовком `X-Telegram-Init-Data`. Сервер сверяет подпись Telegram и время выдачи. Клиент использует `Telegram.WebApp` для открытия и идентификатора гостя.
5. В production установите `APP_ENV=production`, `HOTELIER_API_KEY` и обязательно ограничьте доступ к административным запросам. Для production следует также заменить демо-модель гостевого профиля серверной сессией и проверкой роли пользователя.

## Сценарии для жюри

**Подбор:** открыть каталог и выполнить запрос «тихий номер с видом на закат рядом с морем». Каждый ответ включает объяснение, ограничения и значения характеристик с их источниками.

**Геоданные:** `water_distance_m` рассчитывается формулой гаверсинуса между GPS-координатами отеля и контрольной береговой точкой. Это прямое расстояние, не длина пешего маршрута и не доказательство вида на море.

**Отельер:** в разделе «Кабинет отельера» выбрать отель, ответить текстом на вопрос. Модуль `extract_answer()` извлечёт поле и создаст факт со значением, датой, источником и уверенностью.

**Конфликт:** отправить в `POST /v1/hotelier/1/facts` значение `quiet=false` при уже существующем `quiet=true`. Оба источника сохраняются со статусом `conflict`. Разрешение вручную: `POST /v1/hotelier/1/resolve`.

**Новая характеристика:** `POST /v1/features` с JSON `{"key":"has_garden","label":"Есть сад","description":"Наличие сада","kind":"boolean"}`. Далее можно записать факты через hotelier API без изменения схемы.

**Метрики:** `GET /v1/metrics` отдаёт покрытие, число конфликтов, вопросов и ответов. Покрытие оценивается по доле пар «отель × определённая характеристика», где имеется активное значение.

## Структура

- `app/core.py` — каталог, геометрия, доказательства, конфликты, ранжирование, извлечение ответов.
- `app/main.py` — REST API и авторизация Telegram.
- `web/` — адаптивный Telegram Mini App.
- `data/seed.json` — фиксированный набор учебных данных Сочи, не реальные гостиничные предложения.
- `tests/` — автоматическая проверка расчётов, извлечения, поиска и конфликтов.
- `docs/` — архитектура и интеграция.

## Честные ограничения

Это функциональный демопрототип, а не полностью готовая промышленная платформа. Включены только вымышленные отели, примерные береговые точки и синтетические сведения. Реальные Wikidata/Commons/Mapillary/муниципальные API и живые проверки изменений не интегрированы; вместо них используется расширяемый реестр источников и подготовленные данные. Сценарий отельера построен на правилах, поэтому сложные свободные ответы могут потребовать ручной корректировки. Проверка точности на независимой размеченной выборке пока не выполнена. Бронирования и платежи отсутствуют. Не используйте демо-цены для планирования поездок.

## Безопасность

Для локальной демонстрации кабинет отельера открыт без ключа. В production отсутствие `HOTELIER_API_KEY` блокирует изменения; при наличии ключа он проверяется заголовком `X-Hotelier-Key`. Для общедоступного выпуска обязательны роли, rate limiting, HTTPS, полноценная сессия и управление секретами. Не храните токен бота в браузерном JavaScript.
